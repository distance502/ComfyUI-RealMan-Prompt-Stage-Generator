# 真男人提示词阶段生成器

面向 ComfyUI 的可视化提示词编排节点。它把标签、自然语言、运行时随机、参考图片、角色设定图、视频分镜、NSFW 工作台、本地模型和 API 放进同一条生成链路，输出可直接使用的自然语言提示词，并在模型不可用时保留 Skill 结果。

节点名称：`真男人提示词阶段生成器`

节点分类：`Qwen TE`

节点标识：`QwenTE_StagePromptGenerator`

## 它解决什么问题

- 不再把标签机械拼成逗号串，而是整理为有主体、动作、环境、光线和因果关系的自然语言。
- Skill、本地模型和 API 使用同一份剧情与一致性合同，切换模型来源不会换掉主体或世界观。
- 自动识别并隔离不兼容的场景、服装、道具、动作、镜头和画面媒介，减少串词与无关元素。
- 本地模型请求失败、聊天模板不兼容或候选不合格时，自动回退到可用的 Skill 成品。
- 图像提示词、智能文本、批量结果和视频提示词分别校验，互不污染。
- 角色设定图和图片反推统一生成等宽、等高、同基线的正面、标准侧面、背面三视图。
- 视频输出使用多段自然语言分镜组成完整剧情，不限制字数，也不强塞固定秒数。

## 三分钟上手

1. 将本项目放到：

   ```text
   ComfyUI/custom_nodes/ComfyUI-RealMan-Prompt-Stage-Generator
   ```

2. 完整重启 ComfyUI，在节点菜单的 `Qwen TE` 分类添加 `真男人提示词阶段生成器`。
3. 第一次使用保持 `模型来源 = 仅Skill`，选择模板风格和几个标签。
4. 运行工作流，从 `首条正向提示词` 接到下游正向编码，从 `推荐负面词` 接到负向编码。
5. 需要更具体的控制时，在终端预览中输入智能文本，或开启运行时随机、设定图、图片反推、本地模型/API。

如果更新后界面仍是旧版，先关闭所有 ComfyUI 后端窗口，只保留一份插件目录，重新启动后按 `Ctrl+F5`。

如果完整面板没有接管，节点会显示 `TE MINI CONSOLE` 备用工具栏。GitHub ZIP 常见目录 `ComfyUI-RealMan-Prompt-Stage-Generator-main` 也受支持，但不能与标准目录或旧副本同时启用；需要强制备用模式时可在地址后加入 `?qwen_te_mini=1`。

## 核心能力

### 自然语言图像提示词

所有模式都先建立统一创作主线，再写出自然语言正文。节点会保留用户明确指定的主体、人数、服装、动作、场景、道具、光线、构图和媒介；模板与主题池只补足空缺，模型只负责在这条主线上增加可见细节。

`简洁 / 标准 / 详细` 调整信息密度，不设置硬性字数上下限。候选如果只有分析、占位符、标签串或残缺句，会被清洗、融合或回退，不会直接作为最终提示词。

### 智能编排与定向修复

当前智能引擎会建立场景关系图，并按来源区分用户输入、锁定标签、设定图事实、NSFW 保护项、模板、主题池和运行时随机。自动来源发生明确冲突时，只清理可证明为低优先级且未锁定的内容；用户手动选择不会被静默删除。

主要约束域包括：

| 领域 | 会统一检查的关系 |
| --- | --- |
| 主体 | 人数、是否有人物、正面/侧面/背面、站坐跪躺蹲、动作与支撑物 |
| 世界 | 主场景、室内/户外、季节、昼夜、天气、风势、温度、地表和道具归属 |
| 镜头 | 景别、机位、透视、焦段、景深、焦点平面、镜头稳定性 |
| 光色 | 主光来源与方向、硬光/柔光、色温、黑白/彩色、曝光、对比度、饱和度 |
| 成像 | 媒介、投影、颗粒、锐度、细节密度、雾/烟介质、背景复杂度 |
| 运动 | 高速快门凝固、运动模糊、慢门拖影及对应的轮廓位移反馈 |

模型候选只违反一个轴时，节点会给出该轴的定向修复指令，不重写其他已经正确的内容。明确的转场、状态变化、混合布光和分区设计会保持开放。

### 视频剧情分镜

第 8 个输出为独立的视频提示词。它不是把图像提示词加上“运镜”二字，而是生成至少三段、通常五段的连续故事：建立场景、事件触发、行动推进、局势升级、结果定格。

每段分镜都会说明景别或机位、摄影机运动、主体动作、环境/光线/声音反馈，以及与前后镜头的连续关系。完整故事板必须从 1 连续编号，重复、倒序或跳号的模型结果不会被采用；可识别的建立、触发、行动、升级、收束阶段标题也必须按故事顺序排列。模型只补某一镜时可写明分镜编号，节点会把增量精确并入对应段落，并拦截 `分镜四（触发）` 一类编号与阶段错位。没有编号的一两段短增量会按中英文语义自动落入相应镜头，否定表达不会误导阶段判断，检测到倒序时不猜测重排。推理诊断会显示实际落入的镜头，失败重试也会收到编号歧义、阶段错位或阶段倒序的具体原因。节点还会逐镜追踪主体、服装、主场景和关键道具：首镜建立服装锚点，后续允许用全称、代词、材质反馈或可见状态承接；服装只有在撕裂、沾湿、脱落或明确换装等动作因果直接作用于服装时才能变化，不会因为同镜头里其他环境物件的“撕裂”等词而放行。同一地点内的相邻区域和人物手部特写可以继续故事，但“特写”“内部”或“连续承接上一镜”等弱描述不能掩盖实际切换到新的咖啡馆、海边等地点；跨区域时必须写出同一空间、相邻关系或沿可见路径移动。新道具出现时会提取实际物件名与已选道具比对，拦截“旧信封旁边凭空出现手枪”，但允许拆开已有容器后露出夹层线索。新增主体同样按实际短语检测，同段保留原角色名不能掩盖“另一名陌生男子”，而“不再引入无关人物”一类否定约束不会误触发；原主体无解释变为男孩、陌生人、机器人或其他身份也会被拦截。动作锚点明确要求变身、变形或形态转换时才允许作为剧情变化；若锚点指定“变身为石像”，模型只能使用石像、雕像或对应的 `statue` 同义目标，不能借此改成男孩或其他身份，未指定目标的通用变身动作则保持开放。运行时随机人物图片在没有离地动作依据时会默认建立可信承重关系，并按姿态只选择一个承重点：站姿和蹲姿使用脚与当前地表，跪姿使用膝部与当前地表；坐姿和躺姿只有在自然语言明确接触某个表面，或动作、用户补充、道具层只提供一个可用承托物时才引用它，否则直接使用当前地表。场景背景里的家具只登记为后续可用物件，不自动建立身体接触；同一优先层出现多个候选承托物时也不会按标签顺序猜测，不会为了承重凭空增加家具、台阶或平台。用户明确写出的“人物或承重点 + 站、坐、跪、躺、踩等接触动作 + 具体表面”拥有最高优先级，因此“站在石台上”会保留石台，“坐在地面、沙发只在远景”不会误用沙发，人物仅站在椅子旁也不会被识别成踩住椅面。承重描述会服从已有景别：全身或远景明确呈现脚、膝、髋部等接触点，近景或半身只通过画内骨盆、脊柱和肩线的受力连续性表达稳定重量，不会为了展示画外承重点而扩大取景；未指定景别时使用自适应关系描述，也不会反向强制全身构图。模型候选还会检查“身体承重点、接触动作、具体表面”三者关系：背景物件或站在椅子旁不会误报；单张图片固定一个承托瞬间，即使正文伪装成编号分镜也不能换面；视频只有在编号分镜中明确写出起身、坐下、跪下、躺下、迈上或走上等真实承重变化，并连续交代旧接触解除、重心移动与新接触建立时，才可改用场景中已有的另一承托面，单独出现“然后、随后、接着、转而”不会放行。浮空城、浮空水晶和漂浮颗粒不会让人物自动腾空，显式跳跃、飞行、水下悬停和失重主题仍可正常生成。只在首镜堆入标签、随后无解释换人换景、凭空换装或让道具出现、消失的候选会被定向重试或回退。输出使用自然语言，字数不限。

双人和群像会把承重范围扩展到每位可见人物：每个人分别拥有自己的承重点、重心投影与接触反馈，不能只让其中一人着地，也不能把另一人的身体当作地面或承托物。多人姿态不同时会逐人分配接触关系，例如站姿使用双脚、坐姿使用髋部、跪姿使用膝部、躺姿使用躯干；输入同时提供沙发和床时，“一人坐在沙发、另一人躺在床”会固定为两组独立关系。两人姿态相同但承托面不同时也不会合并：中文的“一人/另一人、第一人/第二人”和英文的 `one person / the other person` 会形成按人物绑定的计划，例如第一位人物坐沙发、另一位人物坐椅子，或第一位人物站石台、另一位人物站地面；模型不能互换人物与承托面。明确人数的三人、四人群像也支持连续序号绑定及英文 `third/fourth person`，但必须从第一位到最后一位完整给出姿态和接触面；少写成员或只写“小队”而未限定人数时会保守使用共享关系，不猜测未描述人物。战士、法师、骑士、游侠、祭司、侦探等互不重复的职业身份也可直接作为成员键，因此“女战士坐沙发、男法师坐椅子”不必改写成序号；人数与具名职业必须完整对应，同职业双人不会仅凭性别前缀强行拆分。多人明确共用同一沙发时仍使用共享关系，不会过度拆分。近景保持原景别，画外接触点不会迫使镜头扩成全身。图片保持所有人物在同一决定性瞬间内的独立承重；视频逐镜保持每个人的支撑状态，只有明确作用于对应人物的承重变化动作才能改变其承托面。若输入明确指定一人飞行、一人站立等混合状态，则只约束明确着地的成员，不会把飞行成员强行拉回地面。

### 角色设定图与图片反推

角色设定图遵守固定结构：

- `1:1:1` 三个等宽区域；
- 正面全身，正对镜头；
- 精确 `90°` 标准侧面全身；
- 背面全身；
- 三个视图同一角色、等高、同基线；
- 正交相机和连续简洁中性背景。

连接 `参考图片` 并启用图片反推后，视觉模型先提取可见事实，再进入同一结构。反推不会把水印、界面文字或无关背景物当成角色设定。

## 模型模式

| 模式 | 适合场景 | 行为 |
| --- | --- | --- |
| `仅Skill` | 离线、快速、稳定 | 不需要模型或 API，直接生成图像、智能文本和视频成品 |
| `本地模型` | 隐私优先、本机 GGUF 或原始模型 | Skill 先生成底稿，再由外接兼容模型或内置本地模型增量润色 |
| `API接口` | 更强语言模型、云端或本机服务 | 支持云 API、Ollama、LM Studio 和兼容接口，仍受同一关系合同约束 |

内置本地模型从 `ComfyUI/models/LLM/` 读取，自动识别两种格式：`.gguf` 走 `llama-cpp-python`；包含 `config.json`、tokenizer 和 `.safetensors/.bin/.pt/.pth` 权重的 Hugging Face 原始模型目录走 `transformers`。两种格式都支持 Qwen3-VL、Qwen3.5-VL、Qwen3.8-VL、Gemma4、Llama、Mistral、DeepSeek 和通用模型。模型文件名中的 `qwen3.8` 或 `qwen38` 会自动识别为 Qwen3.8 家族。节点优先使用模型自带聊天模板；模板缺失或无效时，会按模型家族选择兼容格式并有界重试，避免 `Invalid chat handler` 直接中断生成。Qwen3.8 的专用视觉 handler 按运行时能力可选，旧版 `llama-cpp-python` 缺少该 handler 时仍可加载文本路径并回退到 GGUF 模板。

原始模型目录应直接放在 `ComfyUI/models/LLM/<模型目录>/`，目录至少包含 `config.json`、tokenizer 文件和权重。原始 Vision 模型由 `AutoProcessor` 处理图片；纯文本原始模型可用于提示词、剧情和视频提示词生成。安装 `transformers`、`accelerate`、`safetensors` 后，节点会根据路径自动选择后端，无需新增节点或手动切换格式。

本地加载参数可在模型面板中自定义：上下文长度、GPU 层数、KV 缓存、批处理/微批处理、推理线程、Flash Attention、KQV 卸载、mmap/mlock 和 RoPE 参数均有独立控件。`模型参数JSON` / `内置模型参数JSON` 会按实际后端过滤：GGUF 可传 `llama-cpp-python` 构造参数，例如 `{"n_seq_max": 2, "use_direct_io": true}`；原始模型可传 `transformers` 加载参数，例如 `{"torch_dtype": "bfloat16", "device_map": "auto", "attn_implementation": "sdpa"}`。不支持的键会自动忽略，模型路径、聊天格式和 KV 类型等核心键由节点保护。

API 支持 OpenAI-compatible 接口以及 DashScope、Claude、Gemini 原生适配。通义选择 `通义千问DashScope` 后默认使用 `https://dashscope.aliyuncs.com/api/v1` 和 `qwen3.7-max`；也可自由填写其他通义文本或视觉对话模型名。节点会自动选择 Generation 或 MultiModalConversation 端点，Qwen3/QwQ/QVQ 自动启用思考并只采用最终正文。推荐把密钥写入环境变量，并在节点中填写：

本地 GGUF、外接本地服务和 API 都经过同一个 `model-call` Skill：统一消息结构、响应正文抽取、思考块清洗、空响应判定和通道诊断；网络瞬时错误、参数不兼容或模型候选不合格时，仍由上层重试与 Skill 成品回退处理。

```text
env:QWEN_TE_API_KEY
```

通义也可使用 `env:DASHSCOPE_API_KEY`。旧工作流填写的 `/compatible-mode/v1` 会继续按 OpenAI-compatible 协议调用，并自动补全 `/chat/completions`。

明文密钥会被 ComfyUI 工作流保存，公开分享前必须清空。

## 安装与依赖

项目提供三个 Windows 脚本：

- `内嵌安装到ComfyUI.bat`：安装或更新到 ComfyUI；更新时保留用户标签和搜索配置。
- `一键检查依赖.bat`：只检查，不修改环境。
- `自动补装依赖.bat`：补装可选依赖。

可选依赖：

- `llama-cpp-python`：节点直接加载本地 GGUF 时需要。
- `transformers`、`accelerate`、`safetensors`：节点直接加载 Hugging Face 原始模型时需要。
- `opencv-python`、`rapidocr-onnxruntime`：图片质量检查和 OCR 相关能力需要。

只使用 `仅Skill` 时，无需安装上述模型依赖。

## 输入与输出

可选连接输入：

- `qwen模型`：外接 Qwen/Gemma/Llama 等兼容本地模型对象。
- `参考图片`：用于图片反推或角色设定图提取。

节点提供八个字符串输出：

| 输出 | 用途 |
| --- | --- |
| `结果全文` | 可读报告，包含正向、负向和诊断状态 |
| `首条正向提示词` | 第一条可直接连接下游的正向提示词 |
| `已选标签` | 最终标签和模型/Skill 链路诊断 |
| `JSON结果` | 结构化结果，适合自动化处理 |
| `推荐负面词` | 与当前主体、画面结构对应的负面词 |
| `正向提示词合集` | 本次生成的全部正向提示词 |
| `智能文本` | 智能文本解析和统一后的自然语言结果 |
| `视频提示词` | 连续自然语言分镜剧情 |

## 参数快速开始

默认配置是 `仅Skill / 生成 3 条 / 纯中文 / 标准 / 完整结果 / 平衡收敛`。第一次运行无需调整模型参数；需要批量变化时先开启运行时随机并降低核心锁定，需要模型润色时再切换本地模型或 API。

所有默认值、范围、参数联动和配置方案见 [使用说明书：参数设置完整手册](使用说明书.md#16-参数设置完整手册)。

## 安全与隐私

- 节点不会因队列运行自动搜索网页。
- 自定义 API 地址会执行协议、来源和地址校验；环境变量密钥不会任意发送到未授权来源。
- 预设不保存 API 密钥、额外认证头和运行缓存，但完整 ComfyUI 工作流仍会保存控件中的明文值。
- 搜索可完全使用本地标签库，也可只连接自己的 HTTPS SearXNG。
- NSFW 工作台只面向合法成年内容；未主动启用时不会参与普通生成。
- NSFW 显式动作提供异性与双成年同性角色的插入、口部刺激、手部刺激、单人自慰及成人道具完整合同；旧式器官词与行为词只在成年身份、人数和器官目标足够明确时合并为单条自然语言主动作，避免散装标签串词。
- `潮吹`、`射精`、`体液`及其结果型选项只有在基础动作合同成立且目标部位匹配时，才会附加为同一条“动作结果阶段”；结果不会新增人物、器官、场景或镜头轴线，缺少基础动作时仍保留为未绑定的普通词。
